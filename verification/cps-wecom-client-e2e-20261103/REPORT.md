## 运行方式与真实性边界

客户端通过HTTP查询设备和下发线索；独立接收器按CPS协议验证平台回调。两个真实Node子进程分别运行平台和CPS桥接，两个回环代理实际丢弃受理和提交回包；模拟Agent用平台真实任务／发送凭据／清理协议上报合成结果。客户端签名不导入服务端协议实现，先核对CPS公开签名向量。

本轮专用临时Postgres、实际TCP／HTTP、真实等待121000毫秒，不使用虚拟时钟替代本轮两分钟验证。Android页面、账户绑定、领取、发送及清理证明均是合成fixture；0真实手机操作、0真实邀请、0真实CPS请求，不冒称原生或生产验收。

| 在途执行重启 | 保留原任务和逻辑客户防重，不新建任务 |

| 发送未知 | 不回success／频繁失败；换线索不能再发同一成员与客户 |
| 添加频繁与成员隔离 | 合成固定证明触发failed；仅原成员停止，新客户可由同机已映射分身执行 |
| 最终逐项对账 | 9任务、9次模拟领取、4个合成发送凭据；11回调、7唯一CPS结果；原查名会话与锁不变 |
