# 外部发送前验收：最小合同建议（待批准，未实现）

本轮用户明确“仍只到发送前”。实际32c外部POST只支持send，9槽位纯函数反例及当前线上模块hash已确认；不试探生产send POST。下列是后继独立方案，尚未批准为产品范围，也不代表已有预览能力或部署授权。它延续现有四业务字段、管理员认证、原任务防重及物理隔离；拟增加外部预览资源，**不替换或静默改变现有真实发送接口**。

## 建议接口

- `POST /api/v1/wecom/customer-previews`：沿用管理员Bearer，body仍为deviceNumber/appSlot/phoneNumber/remarkName；路由强制preview，拒绝mode/send/previewOnly等可改执行语义的额外字段，不接受客户端Android用户/ADB身份。已有四字段真实发送路由维持当前行为，不将404或preview失败自动降级到send。
- 预览提交使用稳定`Idempotency-Key`头，客户端在首次请求前生成并保存，超时后继续同key/body；调用方无需增加业务表单字段。服务器按现有user+独立external-preview命名空间持久去重，同key改参数409、重启同key原ID、保存未知503按原key核对；不能靠仅内存map或进行中锁承诺超时防重。具体归档/保留期须在实现前明确，不能承诺无限历史。
- `GET /api/v1/wecom/customer-previews/{taskId}`：同管理员/原preview任务读取；外部send任务、其他管理员任务不能从此接口串读。原send结果接口继续拒绝preview，不把预览当已发送。
- 状态包括queued/running/ready_before_send/needs_attention/unknown/failed。ready_before_send只表示安全到达发送前，绝不表示邀请已发送/对端已收到。可返回remarkSaveStatus说明保存是否确认；UI处理终点与后台物理清理是否完成分开，只有新真实proof持久释放后设备才再次可用。

## 预览真实副作用与保护

预览可以搜索既有授权测试号码、打开客户页及备注页；沿用内部preview策略，仅补空备注/描述，保留已有非空值。它不是“手机零写入”模式；实际保存/未知状态按原任务记录。任何路径均不能请求云端send-claim、创建本地send凭据或点击发送邀请，不能借调试flag进入send。

保持8设备/槽位白名单、物理手机跨槽互斥、全局2任务容量及当前reader预算；不抢控屏/其他任务。查名启用池155/157本轮仍排除。现有43义务不迁移/清除/补造host，预览接口也不能绕过它。外部新路由本身不修复v1跨时钟/真实host证据、SDK隐式自启/退出清理缺口；这些仍是native执行前阻断。

## 最小影响与验证

拟改外部请求解析/新路由和preview结果投影、现有submission gate命名空间、SDK示例新增独立preview/resultPreview方法及API文档。复用现有内部分发/独立物理义务，不整份替换共享Agent/runner/退出回执；其当前归属查名owner，不并行抢写。认证/数据库权限不扩展，不增加第三方永久API Key。

本地先验证：旧send合同不变，新preview强制模式；8设备9槽位；samekey重复/改body/重启/保存失败与丢响应；404绝不fallback send；0 send-claim/0真实发送函数；已有非空备注保留/空值保存/未知不重放；结果命名空间/跨管理员；原物理义务和lookup/控屏互斥；旧客户端/旧服务器兼容。需要真实HTTP、当前持久化模式和适用回归，不拿新的纯函数用例代替。

## 何时才能继续全部机型真机

先形成固定源码/不可变候选、具体发布影响/回滚与root审查；原生时间/ADB和持久化保护条件具备，获具体加载授权后，才能按当时新鲜占用与身份/资源核对串行执行。先23或25（Redmi11），再59（vivo V2357A14）、145（HUAWEI12）；第四种vivo V2442A现有三台均受维护或查名池排除，需独立安全空闲代表，不能自动解除43/更改查名池/扩白名单来补覆盖。

每台一条唯一外部preview任务，原ID轮询直至发送前及实际物理核验，未知停止该机并保留原单；出现共享身份变化/资源不足/其他人控屏则停，不重建ADB或抢位。最后才扩大到其他已配置同型机和155双开；每步均分别记录外部HTTP、真实UI/备注、实际close/新proof和未验项。当前没有执行这些步骤，也不把本方案当作完成用户真机验收。
