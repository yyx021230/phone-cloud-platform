# 历史姓名优先，本地候选

用户要求：同手机号历史查到过姓名，直接返回；历史为空、未实名或没姓名，重新真机查询。本候选基于已提交但未上线的rc.1（`599092d9ae3b1c0e1676d617c20bc09a08a4b34d`），分支 `codex/lookup-name-history-20261023`、标签 `lookup-recovery-20261023-rc.2`。生产比较基线仍是AI deployed.1 / fef7ff8 / 镜像35cba1db。既有修复全部保留，根仓旧业务不作发布源。

## 最终行为

1. 鉴权和用途授权先行。同一Idempotency-Key仍返回原任务，换手机号仍409；历史为空也不能用同键制造第二次执行。
2. 新业务键先找本调用账号、同号码的成功有姓名业务记录，包含Postgres归档，不再限定10分钟；选最近一次有效有姓名记录。更晚的空值/失败不盖掉早先姓名，探测号、其他客户、未来时间和空白/非字符串姓名都排除。
3. 命中历史时复用原lookupId，POST直接HTTP200、`status=completed`、`reused=true`并携带`name`；GET仍可照常读取。没有手机查询、没有队列占用、不延长轮次。平台禁用或账号无授权仍拒绝，手机零容量及轮次停止不影响已有姓名复用。
4. 没有姓名历史时，同号未完成任务仍合并，2分钟超时换键不会重复派发。只有已完成空结果使用新业务键才新建查询，仍受准备/容量/并发/队列限制。
5. 若旧空结果已返回而旧手机尚未释放，新任务保存`waitForLookupId`并排队；调度确认旧预约释放后才派发。后续重复键或新键加入这个新任务，不同时双查；停止/截止时间仍沿用现有逻辑。

历史姓名命中不消耗在途任务的50个别名限额，否则常查同一号码会在第51次被错误拒绝；仅放开已完成正结果的别名计数，在途重复限额保留。旧 `asyncRecentResultMs` 配置字段保留以兼容旧配置，但不再控制本版本姓名复用；不修改生产配置。历史使用已有存储与号码指纹索引，无数据库结构迁移，不建立跨客户共享姓名库，也不改写原结果。

## 组装、发布与回退

使用本目录 `verification/prepare-local.py --out <新临时目录>`；它逐层组装rc.1及本候选，校验父版本、MANIFEST和冻结哈希。本轮未提交生产新镜像、未推送、未上线。`BASELINE.json`同时保存本轮增量及相对实际生产累计16个运行/静态文件的前后哈希。

组装后链接既有依赖，执行 `npm run check`、`npm run test:screen`、`node verification/name-history-http.mjs`；隔离Postgres用 `python3 verification/postgres-name-history.py --runtime <组装目录> --pg-bin <本机Postgres bin目录>`。后两项默认实际等待121秒，不用缓存或静态测试冒充真机。

正式发布仍须最新ACTIVE/镜像/文件核对、备份、空闲门槛、D-075真实宿主只读核验及新维护授权；包含rc.1的Agent分类变更时需明确其加载影响，不以本轮仅云端变更掩盖组合包范围。

**回退前必须排空本轮查询或安全停止至旧预约释放，确认没有排队的waitForLookupId任务。** 旧版调度不识别这个新内部字段，不能在这些任务尚被旧手机阻塞时直接切回。准备经授权回退到实际生产旧镜像/Agent备份及旧静态文件；保留结果、别名和数据，不删除历史、不回填、不自动重查。回退恢复旧10分钟正负结果缓存策略，也恢复rc.1列出的缺陷。
