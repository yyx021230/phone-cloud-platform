## 1. 发布前必须完成

- 授权须指向 `platform-update-20261011-rc.1`，源码 `7f695507761b07504a94b7372de0c340befbf33f`，指定云端/Windows目标、允许中断、窗口及单机→两机验收范围；未经授权不执行后续切换。
- 在实际媒体主机提供获准的 Node 运行入口，执行 `node deploy/mediamtx-pacing/verify.mjs --live`。本轮默认 PATH 无 Node，退出127；只读快照符合D-075不替代该门禁。失败就停止，不自动安装/修复媒体或重启。
- 重查云端镜像 ID、运行文件及 Windows 入口/runner、22冻结哈希；任何漂移先停，不覆盖新生产改动。核对只读配置指纹、挂载、持久目录、磁盘空间、心跳/扫描及正在执行的查名/发布/投屏；本轮没有获取完整活动会话清单，不能推断主机空闲。
- 用维护窗口的新鲜备份保存当前不可变业务镜像、Windows Agent/配置/数据、云端配置与数据、PostgreSQL一致性备份。验证备份可读和恢复路径；本包9份原件只覆盖代码。不得把旧源码快照当完整回滚包，不得整库回灌覆盖新增业务数据。
- 单一发布负责人，暂停新查名并排空原任务/未确认结果/人工交接。不得强行释放占用或取消用户任务。共用Agent入口影响整台主机；只向一台手机发任务不能称文件更新只影响一台。先确认全主机维护范围，或已验收的独占隔离路由；不启动第二个全设备Agent。
- 确保云端 `DATA_DIR/lookup-human-notifications` 和 Windows `dataDir/lookup-status-outbox` 持久、受限、可写。Webhook由受限文件通过 `LOOKUP_HUMAN_FEISHU_WEBHOOK_FILE` 注入，或沿用安全环境配置；不放入包、镜像、日志、命令行或文档。未配置会禁用提醒，正式验收不能漏掉该项。真实通知须在获准测试范围内发送。

## 2. 镜像准备与隔离检查

四档案均须先按MANIFEST及不可变源码标签核对。云端构建上下文只含本轮16文件，Windows档只含6文件；不使用仓根或原工作区整仓发布。

在获准的构建环境加载/保存实际生产镜像并核验 ID 完全匹配MANIFEST，赋予专用基底标签，不能从公共仓库同名镜像推断等价。解开 `cloud-build-context.tar.gz` 到新的空构建目录后，示意命令如下；本轮未执行：

```bash
docker image inspect phone-cloud-platform:baseline-907e0c65 --format '{{.Id}}'
docker build --pull=false --network=none \
  --build-arg BASE_IMAGE=phone-cloud-platform:baseline-907e0c65 \
  -t phone-cloud-platform:platform-update-20261011-rc.1 .
```

第一条输出必须为MANIFEST规定的完整生产镜像ID，否则不执行构建。Dockerfile继承原依赖/健康检查，只COPY最小集合，构建中校验26份云端变更/冻结文件；不会安装依赖、更新系统或媒体。记录新镜像完整ID与来源标签。使用新鲜临时JSON目录、模拟Agent、无生产PG/Redis/凭据/外发的隔离环境验证启动、readyz、静态文档资源、原协议兼容；不可连接生产卷来“测试”。

Windows候选在独立空目录验语法/哈希，沿用当前依赖；不覆盖配置或data。`verify-runtime.py --component windows --state before/after --root <Agent根>` 可只读检查18份；云端组件检查26份。该辅助脚本需要Python；现有云端容器没有Python时由受控外部工具校验，不为检查临时改生产镜像。

## 3. 配套切换与灰度

1. 在已确认空闲且已授权的窗口，确认所有前置满足并记录完整发布回执。云端兼容代码先就绪，Windows入口/模块/runner后配套加载，再开放查名任务；禁止在混版阶段派发冷却v1任务。
2. 只按审核集合切换业务容器和Windows Agent。不得顺带运行通用媒体安装脚本、重启MediaMTX/Windows/ADB/USB/PnP、安装APK或重置画质。Agent加载方式/允许中断须在窗口授权中明确。
3. 记录镜像ID、运行源码哈希、Agent单实例/新鲜心跳、在线/未授权设备与占用基线；核对原结果、冷却、通知回执和未确认报告未丢失。公网健康不等于设备验收。
4. 在明确授权的手机/账号/样本预算内先单机、再两机验收：自然限制准确归属→冷却ACK先于切号；切号后拼图保存新账户/累计次数；手机编号通知；原结果恢复且不重复输入；普通重试直达搜索；漏名格式；全部冷却；结束/取消/并发和跨设备隔离。未实际触发的场景仍标待验，不能用普通成功查询替代。
5. 再次在媒体主机运行标准D-075 `--live`；确认冻结基线、非目标业务和投屏回归。保留24–48小时灰度观察、错误/队列/资源趋势；自然8小时按实际时间验证。未完成观察不能写“生产验收完成”，不自动扩量。

## 4. 停止与回退

出现身份不明/错冷却、任务或结果丢失、重复查询/外发、持续保存失败、跨设备影响、健康或D-075失败即停止新查名；未知状态先按原ID对账，不重提号码。恢复动作应处于窗口授权的回退范围。

先保存新产生的待确认报告/状态与证据，核对任务是否已经执行，然后配套切回窗口前的已验证业务镜像与Agent代码。保留现有配置、数据、冷却/通知回执和outbox；旧版会失去新修复行为，不能承诺混版或旧版继续自动接续。新增13份文件不盲删：核对当前文件仍为本候选哈希、无后续版本引用后按批准方案移出运行范围并保留原件；已有文件按9份源码原件或新鲜备份恢复。D-075独立媒体基线全程保留。

回退后复核版本、健康、Agent单实例/心跳、任务/结果/冷却与回执、设备占用及媒体live门禁，另存回退回执。不用整库旧快照覆盖新写入，不把源码压缩包可解开当成完整回退演练。
