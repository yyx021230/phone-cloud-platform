# rc.12：对外就绪状态与五条业务窗口（本地候选，未上线）

用户明确：对外不返回手机数量；内部至少两台真实探测通过才就绪。每调用方最多同时五条未完成业务，只有两台就绪时两条执行三条排队，后续手机就绪立即接队列，逐条返回。

实现：prepare HTTP响应仅白名单输出ok/preparationId/status/ready/expiresAt，内部数量和阈值保留用于调度。prepared客户端按clientId在同一事务内检查五条未完成业务；排队/执行/人工/恢复/未知均计入，探测不计入；同键、同号码在途和近期结果去重先于限额。第六个新号码429 lookup_inflight_limit，未建任务、未占请求键；有结果后使用原键重试。既有跨机转交仍需确认触限与停止ACK，不盲目复制未知执行。

动态补位复用既有就绪调度：两台忙时三条在平台公共队列，不绑定忙碌手机；第三台完成探测后立即获得最早待派任务，后续同理。一条先完成即可读取并补下一条，不等整轮。外部接口、OpenAPI和ZIP接入包同步；SDK实现原来只依赖ready，无需数量字段。旧的未prepare客户端不改变原合同。

验证：本地真实HTTP/HMAC及模拟五设备、调度/异步/SDK等108项通过，新增租户隔离及异常占位断言后定向全部通过；Python SDK4项、根语法及生成文档/ZIP哈希检查通过。旧接口数量泄漏和旧十条同时受理均复现失败。未连接生产或真实设备，本轮未跑全仓/真实PG，不将模拟当真机。前序rc11的156页面补丁作为累计依赖保留；其原请求和自然触限/冷却待验状态不被本轮结果覆盖。

兼容：对外删除四个数量字段是用户明确要求的契约收紧；依赖旧数量字段的接入方须改成ready/status。新prepared客户端增加五条窗口，旧未prepare合同保留。新服务回退旧服务会恢复数量字段和旧容量，不删除任何请求/结果/别名。已存在超过五条的存量请求继续执行，回落后再接新单。
