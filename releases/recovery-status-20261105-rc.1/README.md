# 在线旧隔离与恢复队列状态修复

版本：`recovery-status-20261105-rc.1`。状态：**本地候选，未上线**。

## 目标与已确认原因

2026-11-05 的只读样本中，28 条持久化隔离有 22 条对应 ADB 在线设备。云端与 Agent 的恢复控制 revision 均为 52，不能归因于解除请求没有送达。该样本不是当前持续在线承诺。

现行 `confirmed()` 拒绝清除已有 `isolatedAt`；正常稳定校验只覆盖仍有恢复 attempt 的设备，历史隔离自然恢复后没有闭合入口。前端又把暂停/隔离记录补进实时恢复队列，导致在线手机看起来仍需恢复。两者共同构成状态缺陷，不代表 USB 硬件故障已经修复。

## 最小变更

- Agent 复用现有直接 ADB 发现快照，不增加扫描或设备命令。只有连续在线至少 90 秒且至少 3 次不同的新鲜扫描后，才持久化清除该设备旧隔离/失败计数；30 秒扫描间隔通常需要 4 次样本。
- 离线、未授权、缺失、重复序列号、陈旧/倒序/未来快照、漏扫、进程重启或新故障均不能沿用旧证明。落盘失败仍保持隔离。慢磁盘不阻塞设备上报、不堆积观察任务。
- 保留一条最近隔离审计和恢复时间，保留 release revision。人工暂停属于另一存储，不会被自动解除。
- 管理页仅把真实异常队列计入恢复数。历史隔离/人工暂停单列为设置与记录；正常手机不出现“解除隔离并继续”动作，避免为清理显示而触发恢复。实际异常、未授权与正在收尾的恢复动作仍显示。
- 保留设置提交、等待确认、管理器离线与已确认的原有反馈。空队列不推断全部手机正常。

风险为 R2：改动共享 Agent 的状态闭环，必须回归设备发现、暂停回执和投屏控制。未来生产激活属于 R3，需另行明确授权及空闲门禁。本轮不发布、不重启服务或设备，不改恢复动作链、SYSTEM ADB 身份/授权文件、调度、USB/PnP、Hub、手机、投屏、画质或 D-075。
