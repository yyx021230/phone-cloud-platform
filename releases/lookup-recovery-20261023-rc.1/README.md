## 问题和本次处理

跨夜轮次截至10月23日08:52有2145条业务，80条空值走缺图分支，其中47条上游为输入变化；抽样证实有姓名漏读，也有退回搜索输入页的情况。不能把80条全部算成无姓名或全部算成漏名。唯一失败记录为156号任务返回 `task_failed/server_error` 且快照文本为 `Killed`；原图有姓名，却未接续。统计口径及证据见[跨夜分析](../lookup-ai-live50-20261022/OVERNIGHT_ANALYSIS_20261023.md)。

1. **有截图却关联不到**：合入尚未发布的AI rc.2。按同一任务、拍摄时间、字节数和MIME唯一匹配finish事件中的截图，仍检查原请求、会话、代次、时间和摘要；不取其他任务图片。
2. **输入丢失或退回搜索页被当成结果**：将明确的输入变化、前台变化、恢复输入不匹配划为导航状态异常，不进入AI空值收尾。输入丢失先同机做一次普通恢复；恢复仍失败、输入不匹配或前台改变则等待旧会话停止确认后，保留原外部查询ID转交。现有三台上限、请求截止和取消规则仍有效。
3. **非空搜索文字被当成空框**：同机补输入必须证明输入框文本真正为空；推荐文字或其他文本不能仅因“没有数字”而被覆盖。已有有效姓名结果仍优先读取。
4. **执行进程异常退出直接失败**：只对精确的 `task_failed/server_error/Killed` 组合补接续，必须同一设备、调用方、会话、代次和查询，job/task均已失败；不把所有泛化错误盲目重试。停止ACK后才跨机，原查询ID保留。进程为何被Killed仍未证实，本次修的是恢复缺口。
5. **账户准备漏处理USB提示、风险分类不清**：账户导航接入已有ColorOS精确“忽略”处理，不切USB模式；启动设备风险独立报内部原因，不给未知账户写冷却或盲目切号。

5个运行文件的前后哈希见 `BASELINE.json`。Agent入口仅增加错误分类，不修改共享调度、生命周期、ADB、SYSTEM、密钥、USB、媒体或控屏。400个范围外文件逐一哈希一致，包括前端/API文档及投屏基线。四个公开HTTP接口、API Key、姓名/空字符串契约、AI整体120秒限制、最多5台调度均不变；本次没有数据库迁移或依赖更新。
