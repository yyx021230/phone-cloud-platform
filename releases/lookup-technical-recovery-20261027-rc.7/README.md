# 搜索刷新后持续异常与故障验收 rc.7（本地候选，未上线）

基于 `bcd5219ba3eaf00024c1ab9fed1c139aa959829a` / rc.6，分支 `codex/lookup-preparation-recovery-20261027`。继续以 `BASELINE.json` 的实际生产源码64148f3、镜像5ab68ecb为运行基线。累计13个产品覆盖文件，本轮相对rc.6只修改 `windows-agent/scripts/alipay_name_lookup.py`；其他12文件原样继承。无新增依赖、迁移或线上配置变更。

## 本次规则与实现

用户本轮明确：搜索结果页“网络不太顺畅”在刷新后仍持续，属于账户限制。此规则替代rc.5/rc.6对这个**已完成刷新且持续显示的精确分支**的临时网络退避；不把一般网络错误都归为账户限制。

原有搜索页、原号码、两帧按钮定位、前台页面与拼图/限制保护均保留。刷新成功一次、至少5秒后再次读到相同网络错误，发出既有 `frequent_or_abnormal_access` 账户限制信号，并以 `restrictionEvidence=network_refresh_exhausted` 和 `visual-network-after-refresh` 留下来源。账号身份核验、8小时冷却写入确认、切号准备、探测与原ID跨机沿用现有链路。点击失败、短观察预算、页面变化、离线、读取器失败不能使用此新分支；不返回空姓名、不送结果AI。

## 112实际取证

当前为蜂窝数据联网，支付宝UID未被Android网络策略阻止；两个支付宝相关域名的DNS解析与ICMP回复成功。应用进程日志未提供可读错误行，不能据此证明没有应用错误，也未取得支付宝服务端限制原因。系统连通性证据与用户确认的业务规则分别记录，不能把新分类冒充服务端根因证明。

本轮本地HTTP服务调用实际候选Agent任务/账户函数，再连接Windows独立暂存脚本。112再次自然出现网络错误，720×1612画面实际刷新点击为(360,603)，位于原图按钮内；5.609秒后仍是原错误页，当前账号身份已核验。真实限制信号经Agent写入**隔离测试库**的8小时冷却，再自动启动同机切号。生产结果、冷却与池配置未改。

自动准备及切号96.766秒：选择已保存账户，处理自然全屏广告，重新核对当前账户，暖返回未额外force-stop，最终回到搜索页。这个证据覆盖自动路径的120秒预算；其设备是112，不能写成154本次同样耗时。新账号探测遇真实拼图，需人工完成后才可授予就绪。

## 154输入前恢复验收

测试专用wrapper在实际候选Python的输入前导航边界注入一次真实故障同形的RPC读取超时，不修改候选产品文件，不中断设备网络/ADB。实际Python加上输入前标记，实际Agent选择 `reattach_before_input`；旧worker确认退出，再执行原任务。第一次无输入，第二次进入真实搜索输入，未触发应用重启；后续出现真实拼图，保留原任务等待人工接续。

这是**故障注入＋真机完整路径**，不是本轮再次自然复现154相同超时。不能将受控注入、142上一轮自然提交后超时、112自然网络限制混为同一次故障。

## 验证与限制

实际结果和未完成项以 `evidence/RESULTS.json` 为准。Python测试覆盖刷新后账户限制、成功刷新后正常读取、点击失败、短观察预算、拼图优先。JS专项通过真实Agent分类函数与账户策略验证冷却ACK、原任务交还以及技术错误不误冷却。

真机桥接运行实际本地HTTP、任务/账户函数和Windows候选脚本，但不运行生产共享Agent主循环/outbox；不能称生产外部接口验收。手机独占通过已存在的平台租约，逐操作核对自身session；生产ADB20316与Agent14540固定SYSTEM，不重启、不切换身份、不修改共享服务。真实截图/手机号/账号/租约只存私有临时目录，仓库保留脱敏摘要与哈希。

## 最终复验结果

首轮保留了112自然限制、96.766秒自动切号和人工后成功探测的实证；154的后半程受测试工具动态名单遗漏影响，没有计为成功。辅助工具改为固定原测试范围、每个任务核对精确租约、每次读取单独留证；未抢占其他控制者，没有修改生产工具。

修正工具后，带入所有实际生产及前轮测试冷却，重新走本地完整HTTP链路。154输入前注入错误12.390秒返回；同任务重接读取器37.891秒后成功读到探测姓名，两次worker合计一次输入、一次提交、零应用重启。112、154均真实探测通过，只提交一条后续业务，接口completed返回空字符串；原截图只有充值快捷功能和推荐，没有姓名卡，人工复核与返回一致。结束接口stopped，两台自有租约及独立测试worker归零。

根静态检查、1348项JS串行回归加6项新增Agent集成、600项Python加163项runner、43项Windows专项均通过。新增网络规则测试先在旧候选得到2项预期失败，再修正产品后通过；未隐去首轮辅助脚本失败。共享Agent、ADB进程/身份及13个生产文件哈希未变。

**未完成项**：154同形RPC错误本轮是受控注入，未再次自然触发；业务查询阶段的“刷新后持续网络错误→原ID跨机”本轮没有自然复现（实际探测切号已通过、业务分支由真实分类与账户策略集成测试覆盖）；最终候选的PocoService系统崩溃弹窗、新8小时冷却自然到期未重新等待复现。112的自动切号耗时不能替代154设备自己的自动切号耗时。本轮不宣称所有故障真机验收完成或已可上线。
