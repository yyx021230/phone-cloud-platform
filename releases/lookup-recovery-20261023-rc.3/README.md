## 修改内容

1. ColorOS“已允许USB传输数据”精确提示沿用“忽略”元素。点击前核对前台仍为ColorOS；点击后须确认支付宝实际回到前台。焦点null、未知或其他应用不能算关闭成功。新增关闭确认事件，关闭失败不继续点底层账户界面，不改变USB模式。
2. 启动时遇到精确支付宝设备风险标题和提示，先确认支付宝前台，发一次返回，重新读页面；风险已消失才继续正常账户准备，拼图/登录/真实限制回到各自流程。风险持续或前台不明则结束本次恢复，不循环返回、不猜账户、不因风险弹窗写账户冷却。本项替换rc.1“风险一出现立即暂停”的策略，依据用户本轮明确要求。
3. 同机恢复发现搜索框文字不匹配时，区分推荐文案与实际输入：推荐文案可能通过辅助功能呈现为text；需精确搜索前台、唯一输入框，以及实际输入连接的两次零长度确认，才允许补原号码。真实非空内容、未知焦点、登录/拼图不被覆盖。观察模式仍保持只读，正常恢复模式才允许这一步。原结果先读、原查询ID及有界恢复保持。
4. 准备探测的输入变化也先在原手机恢复一次，要求同一账户/Agent身份与已终结原任务证据。修复探测attempt没有readinessIdentity却已有channel.queryIdentity时不能进入普通恢复的问题。再失败释放占用，避免一轮探测卡住；不无限重试或提高并发。
5. post_human_check和human_probe使用自己的事件文案，避免默认显示“结束会话”。新增不含手机号/输入文本的状态证据；未修改共享ADB、任务调度器、生命周期、投屏或SYSTEM。

本轮运行文件仅server/managed-lookup.mjs、windows-agent/scripts/alipay_name_lookup.py、windows-agent/src/index.mjs；测试和验证脚本另列MANIFEST。407个父候选范围外文件哈希一致。累计生产差异16个运行/静态文件，包含父候选的截图关联、恢复、历史姓名及接口文档，不能只部署本轮3文件而遗漏依赖。
