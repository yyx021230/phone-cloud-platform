# 161 空闲真机的分段耗时（2026-10-26，本地候选）

同一台161，通过Windows安全SSH运行独立暂存脚本。用户允许占用一台空闲手机，后明确正在控屏观察并允许测试继续；不关闭其观察连接。生产Agent/ADB PID分别14540/20316，均SYSTEM；未替换生产脚本。

| 路径 | 观测 | 结论 |
|---|---:|---|
| 初版准备 | 27.6秒失败 | 底层“全屏广告”元素遮蔽实际Canvas实名弹窗的分类；不是账户限额 |
| 关闭已有实名弹窗后完整准备 | 71.3秒成功 | 账户列表稳定读取约6.3秒；账户确认后又冷启动，返回搜索约22.7秒 |
| 测试探查输入 | 18.9秒进入真实拼图 | 原号码保留，未以空结果收尾 |
| 误用只观察模式接续 | 58.8秒失败 | 测试驱动配置错误；页面是原号码+键盘的搜索输入页，不能计入正常查询速度，也不能声称AI漏识别 |
| 正常拼图接续 | 22.3秒返回姓名 | 同一号码/请求，无重新输入；完成搜索提交，Windows本地OCR两帧约9.1秒 |
| 初次免冷启候选 | 57.0秒失败 | CLEAR_TOP返回仍停“我的”标签；真机发现后补首页元素确认 |
| 补首页确认后完整准备 | 59.1秒成功 | 账户确认后回搜索约18.2秒；一次准确首页标签点击，无第二次force-stop |

71.3与59.1秒两轮起始页面不同，不能作严格A/B或承诺固定百分比；同一返回阶段约节省4.5秒也只是单机观测。保留3–10秒既有输入间隔、两帧结果确认、登录/拼图/限制保护。普通查询不走首次账户确认。

叠层新分支有真实截图识别（精确标题/动作/唯一圆X，720×1600坐标360,1252）和状态模拟覆盖；完整真机准备重跑成功，但该次先关闭了已经可见的实名提示，不能声称新“底层广告+晚到实名”分支已经再次自然触发。

测试占用最初使用普通控屏接口但未连接控制WebSocket，遇到browser_connect_timeout；后改用有心跳的控制连接，随后释放供用户完成拼图。用户明确观察期间继续后，仅161允许在该观察连接下测试，不抢其他手机、不关闭用户控屏。未观测到161被线上调度并发接管，后续每条测试均核对无池channel。
