## 使用方式

管理员进入「查名字」查看统计；右上「调度设置」修改并发。点击「添加白名单手机」，从平台库存勾选，加入待保存名单后点击「保存设置」。改并发或白名单本身走已有持久化配置接口，不要求为每次设置修改重新部署；首次交付这一功能仍需发布应用版本。

- **业务统计**：累计查询、今日新增、今日完成、有姓名、空结果、异常/超时、取消、今日参与查号手机。
- **实时调度**：处理中、排队、需要人工、探测通过；白名单总数、启用数、基础条件可用、暂不可分配、正在探测；仍保留手机账号表、查询详情和历史截图。
- **调度上限**：初始默认5台；管理页面可设2–1000，含准备探测和业务查询的物理占用。后端保留旧配置1的兼容，但首次准备仍至少2台通过，因此页面不建议配置1。1000是输入及配置大小保护，不是千台真机性能承诺。
- **动态增减**：增加上限或添加手机会唤醒当前有效轮次的补位需求，新手机须满足基础条件并探测通过；没有有效轮次时不自动启动。减少上限不强制停止已有业务，已占用数可能暂时超过新上限，后续自然收尾并释放空闲多余会话。已有探测节流、人工保护、设备排他和业务优先保留，不承诺立即补满。
- **白名单**：移除原49个编号及49台数量硬校验，最多保存1000条；只接受平台库存中唯一匹配的数字手机编号及真实设备ID。离线库存可加入，但不会因此授予就绪。不会自动勾选全部库存。已有启用手机可停用或移除；仍有查名通道/保留占用的手机拒绝直接停用、改绑或移除，防止破坏原查询。先正常释放后再调整。
- **保存保护**：配置串行事务、版本冲突返回409、管理员权限、错误输入整笔回滚；已有手机的冷却关联、准备失败、账号掉线及公平调度记录保留。外部API Key不能修改配置。每客户未完成任务上限仍独立设置，默认20，不随并发数自动变化。

## 统计口径

累计与新增按唯一原查询ID计数，不是不同手机号去重数，也不是HTTP调用次数。探测、幂等重放、原ID跨机接续不重复增加。正向历史命中复用旧ID，当前不算新建查询；不能把此统计当作全部外部API访问次数。

今日为Asia/Shanghai自然日。今日新增按createdAt，今日完成及姓名/空/异常/取消按completedAt，因此昨日提交今日完成也计入今日完成。今日参与查号手机按业务attempts.at及deviceId去重，探测不计。运行中结果不伪造空；空结果只是已记录的返回值，统计本身不重新判断内容正确性。

PostgreSQL在单条查询快照内合并当前requests与归档结果，当前记录优先，按原ID去掉重叠，数据库端聚合，不把全部历史手机号/姓名拉回浏览器。JSON路径按同口径计算。累计覆盖系统仍保留的所有业务记录；不推断已清理记录，不回填未知历史。后台5秒刷新和原有鉴权/截图证据权限保留，统计不操作手机。
