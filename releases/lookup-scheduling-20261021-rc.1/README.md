## 行为变化

1. **统一5台占用预算。** 查询、探测、待命、人工等待均占预算；停止中必须等ACK。已持久隔离并禁止继续执行的离线旧设备不计工作预算，但物理清理锁保留。升级前遗留的超额占用安全收敛，不强行中断正在控屏/执行的手机，也不承诺升级瞬间卡片就只有5台。
2. **观察不再受执行满槽限制。** 同一挑战、同一会话和控屏身份连续两次确认搜索页，间隔2–30秒，才记录验证完成；确认30秒有效，重启必须重新观察，未知/重新出现拼图撤销确认。满槽时保留有效证据，调度先接续已完成人工的原任务，再派新业务/探测。Agent只读观察每机不重叠、总计最多3个；慢手机不会阻塞其他观察结果上报。
3. **卡片每2秒独立刷新。** 明确显示“验证检测中”或“验证完成 · 等待接续”，不用整页刷新。停止、账户掉线优先级保留；不重建控屏DOM，不显示手机号/姓名/账户诊断。2秒是刷新周期，不是对真实手机检测耗时的承诺。
4. **原机恢复优先。** 健康空闲5分钟仍优先原机重探；确认账户触限后，原业务等旧执行stop ACK再原ID跨机，原手机获得一次优先重新启动探测机会，复用既有账户切换及8小时冷却策略。账户掉线、全部冷却或不健康仍不可强行派单；单次优先机会不变成无限重试。
5. **就绪手机轮流接单。** 持久化业务分配序号，优先空闲且就绪、最久未接业务的手机；探测不推进业务轮次。人工刚恢复有一次接单优先，之后回到轮转。快手机不等待慢手机，所以不同速度下不强求最终条数相等。
6. **人工长等有界补位。** 超过2分钟仍未确认完成、没有控屏占用、能够安全停止且确有健康候补时，先停止旧会话，ACK后释放；原业务ID继续排队，原机退避5分钟。未收到ACK不扩容，正在控屏不停止。此值是本候选内部策略，不代表客户端2分钟HTTP超时会取消请求，也不替代账户8小时冷却。
7. 保留父候选精确的页面恢复耗尽分类和原ID跨机。迟到结果、重复提交、取消、结束本轮及下次启动仍按既有门槛处理，不把异常当空姓名。
