## 本次修复

1. **有姓名但没有转账/加好友按钮的紧凑结果卡**：给OCR与AI增加独立严格规则，不虚构按钮。必须是单张个人卡、号码精确匹配、姓名/号码处于“人”和“快捷服务”标题之间、几何布局正确且下方有同号码充值入口；部分按钮、多个卡、跨区文字、遮挡或证据不足仍拒绝。原有普通卡规则和OCR置信门槛保留。
2. **账户列表误报不稳定**：读取列表仍需两帧完全一致。原12秒总预算与底层读取耗时不匹配；现在列表总预算24秒，每次完整读取最多8秒，给第二帧保留时间。过期帧不接受，设备传输错误向上原样分类，不再混为列表变化。不会重复点击“登录其他账户”。
3. **结果到AI前重复长等**：首次查询已经结束，且明确为结果观察耗尽/卡片无法证明/卡片变化，并有同任务、同号码、同账号、同代次的已验证截图时，直接进入既有AI处理，省去第二次完整观察。未知页面、输入丢失、网络错误、截图缺失仍走相应恢复；模型整体120秒上限与停止/迟到结果围栏保留。
4. **普通恢复误提示人工**：保留query_resume不重复输入的执行方式，另外传递恢复原因。普通页面/设备/网络恢复显示“查名自动恢复中”；真实拼图仍按人工流程处理。旧记录没有来源时保留原有兼容行为。
5. **失败后缺少识别耗时证据**：查名执行器保留最多40条白名单诊断，包括OCR/账户列表步骤、耗时、计数和枚举原因；异常退出也带回。新增诊断不保留号码、姓名、OCR原文、坐标或任意模型响应。AI拒绝补充内部分类，外部仍按既有姓名/空字符串契约，不新增结果类别。

完整候选继承rc.1：网络提示先定位刷新一次，系统USB/升级弹窗先元素、缺元素再严格OCR双帧定位，关闭后重新识别；探测结果有姓名但元素缺失时使用同任务原截图AI证明就绪。以上均保持有界恢复、同ID跨机、并发上限与已验证历史姓名命中逻辑。不是任意页面都交给AI点击，也不扩大未知弹窗的点击权限。
