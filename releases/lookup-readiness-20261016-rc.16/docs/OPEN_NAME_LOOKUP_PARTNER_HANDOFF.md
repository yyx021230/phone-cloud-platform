# 合作方交接检查

本包版本lookup-readiness-20261016-rc.16，实际部署与验收范围以同版本发布回执为准。管理员确认部署与设备池开放后，按本包不含设备数量的准备响应对接。

需要单独交付：HTTP BASE_URL、clientId、secret；平台内部配置已授权且已知有姓名的探测号码，不交给调用方。新Agent支持lookupRuntimeId才能出具本轮准备证明。调用方仅按ready/status判断就绪，设备数量和调度由平台内部管理。

流程：prepare（{}，持久准备键）→ready→tasks（phoneNumber，持久业务键）→按lookupId GET。每条完成立即回填name，未实名为空；处理中不回填空，服务错误不当空。准备任务和手机号业务是两类ID/键。

合作方至少测试：真实签名；准备中时503、返回ready:true后可提交；两分钟后换键仍原ID；响应丢失重试；一个号码先完成就先保存；姓名/空姓名；GET失败不重提；回填失败重读；准备过期新键、账号掉线后准备降级。五台模拟不是五台真机。

SDK默认每次HTTP30秒，POST网络错误最多再试1次且复用键；每次新Nonce/签名。保存name需同时满足ok=true与status=completed。旧客户端没调用prepare时仍有succeeded/not_found/failed，新示例兼容旧完成态；不要在一个clientId下混用旧解析器与新prepare流程。

本地和生产证据以版本回执为准；本包不含真实手机号、密钥、姓名或服务器登录信息。没有改变媒体、ADB、USB或投屏参数的授权。

每个clientId默认允许20条未完成业务（执行与排队合计，可由平台管理员调整）；可以并发提交10个或20个单号码请求。平台内部最多5台执行，只有2台就绪时其余请求排队，其他手机通过探测后自动接后续任务。哪条完成就单独返回，不等整批。达到配置上限的新号码返回429 lookup_inflight_limit且不创建任务，保留原业务键稍后重试；重复请求先防重、不额外占名额。客户端超时不会取消原任务或释放名额。

就绪状态会随手机当前情况变化；长时间无查询后平台会要求重新探测。若新提交返回503 lookup_not_ready，保留原业务键，用原准备键读取prepare直至ready后重试；已受理任务继续按原lookupId读取，不能把准备降级当作无姓名。准备轮次固定30分钟，反复读取不延长租期。
