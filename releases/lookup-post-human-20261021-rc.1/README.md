## 拼图后的处理矩阵

观察器只报告页面枚举；任务执行前另读一次当前页面，不能拿旧截图/旧回报直接切号、写冷却或认定成功。

| 当前证据 | 后续处理 | 卡片/结果 |
|---|---|---|
| 拼图仍在或再次出现 | 保留原请求，等待人工；沿用原人工期限及替补规则，其他手机继续 | 需要人工拼图 |
| 正常搜索页/结果页 | 连续两次确认后取得执行位置，再次读取；精确原号码已有可信原生姓名结果时直接读取，否则恢复既有探测及原请求链路 | 检测中→验证完成等待接续→查询/完成 |
| 完整无姓名结果、未实名号码 | 仍走既有完整页面、号码、已就绪账号与视觉证据规则；本次快速守卫不凭空白/缺元素提前判无姓名 | 确认后最终空字符串 |
| 明确账号限制 | 业务已有确切账号时先保存并确认8小时冷却，原请求按既有安全停止ACK转交；原机优先走已保存账号选择和重新探测。启动阶段未确认身份时先进入既有账号确认，不能按缓存账号记冷却 | 检测到账户限制→切号/重探；全部账号冷却则进入冷却 |
| 明确登录页 | 执行端复核后进入既有账号掉线通知与本轮排除；业务原请求安全转交，下次启动可重新探测 | 检测到登录页面→账号掉线；账号未知时不编造账号 |
| 已知实名认证弹窗/支付宝首页 | 复核后交给既有精确弹窗关闭/搜索导航流程，不在观察器里点击 | 验证后页面恢复中 |
| 加载中、网络提示 | 新鲜观测持续60秒仍未恢复才进入一次有界复核；恢复成已知状态即按对应分支处理 | 页面加载中/支付宝网络异常，不伪装成拼图 |
| 未知弹窗、其他应用、结构不完整、前台变化、UI读取失败 | 不盲点、不返回空姓名；持续新鲜观测60秒后有界复核。启动探测仍未知则停止该探测、退避5分钟，本分支不增加三次设备失败计数。业务仍未知则沿用一次原机只读结果恢复，之后明确页面待兼容，保留原请求并受原期限和结束接口约束 | 检测中/页面待兼容，其他手机继续 |
| 息屏、设备忙、无法确认电源 | 不冒充验证通过，不抢用户控屏；等有效观测或沿用原人工/任务期限 | 息屏或检测中 |
| 手机/Agent离线、明确传输故障 | 沿用30秒离线隔离及原请求转交、停止ACK/旧代际拒收逻辑，本次不重建ADB | 离线/恢复；原业务不伪造空姓名 |
| 用户结束、本轮15分钟空闲结束、原请求超时 | 既有取消/安全停止/离线隔离优先，旧观察和迟到成功不得重新启动任务或覆盖已完成结果 | 停止/结束/明确错误，已完成结果保留 |

规则延续首次至少两台才开放、开放后可零就绪排队、最多5台预约/执行、公平分配、原机5分钟重探、15分钟空闲结束；本次不改这些数值。所谓闭环是每个状态都有处理或明确终止边界，不是把无法识别页面都当成功。

## 防止旧状态误操作

- 相同challenge、控屏会话、Agent及新鲜租约；同一可处理状态连续两次、间隔2—30秒；旧回报/乱序/重启前观测不能接续。
- 限制、登录、弹窗恢复和未知复核等待用户退出实时控制，不强占。正常搜索页保留原来已绑定人工控屏的交接规则。
- 观察异常连续计时要求同一状态/challenge/控屏会话且间隔不超过30秒；设备忙或电源未知不启动60秒复核。
- 执行端新增 `post_human_check`：一次有界页面读取；复核失败后不重启支付宝、不额外重建worker、不降级XML点击。若拼图重新出现，立即回人工分支；若前台/号码变了，不返回旧姓名。
- Agent声明 `lookupPostHumanProtocol:1` 后云端才允许新托管人工接续。旧Agent会保持等待，不会把新守卫误当普通查询。
- 已有原结果正例直接读出；其他情况继续既有内部探测验证，不向外暴露设备数、账号或内部状态。
