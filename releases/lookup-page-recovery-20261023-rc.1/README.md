## 解决的问题

1. **网络结果页**：112号原图的“网络不太顺畅／请刷新页面或检查网络设置／刷新”不在旧识别器的“网络有点忙／刷新试试”规则内，最后被AI按空处理。现在两种完整提示都识别；精确搜索 Activity、同一输入号码、非拼图/限制页及连续两帧相同按钮得到确认后，优先使用元素，缺元素时使用OCR框中心点刷新一次。保留原号码，不重新输入、不切号；给刷新结果3秒观察机会，仍受原查询预算约束。正常结果仍需要新的两帧证明。
2. **探测有姓名却失败**：保留前一候选的探测AI入口。原探测任务已经终止且同账号/代次/轮次的原截图证明当前测试号码有姓名，才补充就绪；不会因空、未知、超时、缺截图、停止或迟到结果授予就绪。此项不是“所有探测失败都改成功”。
3. **系统弹窗与拼图后闭环**：152号拼图后进入USB提示，旧post_human_check直接unknown退出；86/121的OriginOS升级阻挡启动。现在未知页面返回共享弹窗识别，并在已知系统窗口挡住Poco时先处理窗口。ColorOS只点“忽略”，OriginOS只点“稍后提醒”；优先元素，缺元素时核对完整提示、精确前台包、底层支付宝、两帧一致的文字位置。只点一次，焦点消失和重新识别页面后才续原步骤。未知窗口、坐标变化、重复按钮、超时均不盲点。普通人工观察human_probe保持只读。

真实截图接到完整处理函数时，隔离OCR在最初8秒预算下发生过一次超时。现在仅post_human_check查名复核任务上限从12秒调整为45秒，内部系统OCR最多共享30秒，为后续分类留出余量；不增加ADB命令超时。普通系统弹窗OCR预算18秒、整条共享恢复最多3个不同弹窗，每种只尝试一次。Windows的既有隔离OCR进程负责原生推理超时，未变更依赖、解释器配置或模型。

**已知网络错误不能再走AI空值收尾**：云端将其区分为内部network原因；确认原执行终态并收到停止ACK后保留原lookupId跨机。继续复用现有最多3台恢复限制、并发5台、取消/代次围栏，不扩展外部成功返回字段。探测网络失败计页面退避，可受控重探，不写账户冷却或硬件不可用计数。
