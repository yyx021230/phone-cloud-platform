# 合作系统接入：提交手机号、获取姓名

交接版本 `lookup-delivery-20261014-rc.1`。生产双接口已部署；本次恢复修复须完成上线验收后开放合作方联调。平台内部负责49台名单、最多5台并发、切号、冷却和人工处理，对方无需传设备号。

## 交付与配置

交付压缩包内的 OpenAPI、完整协议、Node/Python SDK、签名示例和本文件保持同版本；先核对 SHA256.json。管理员单独提供 HTTP BASE_URL、CLIENT_ID、CLIENT_SECRET 并开通设备池用途授权；真实凭据不放代码、文档或日志。SDK内置HMAC，不需要把账号密码或设备号放在JSON里。姓名是支付宝实际显示的掩码姓名，无法承诺完整真实姓名。

## 两个独立任务

1. **提交任务**：先在业务库创建稳定业务ID和Idempotency-Key，再 `POST /api/v1/open/name-lookups/tasks`，JSON仅 `{"phoneNumber":"13800000000"}`。保存返回的lookupId；202是新建，200是复用，都表示已受理，不能直接当作查名完成。
2. **结果任务**：每5秒加少量随机延迟，`GET /api/v1/open/name-lookups/tasks/{lookupId}`。每个号码完成就单独回填，不等整批；lookupId需要HMAC认证。建议每次有界扫描并轮换记录，避免前几条长期处理中挡住后面的读取。

| GET status | 调用方处理 |
|---|---|
| queued / processing | 保存原ID，下轮继续读取；不回填空姓名 |
| succeeded | 将name原样回填，按业务ID/lookupId保证只回填一次 |
| not_found | 明确无姓名结果，独立记录状态；name为空 |
| failed | 本次执行失败，保存code并告警/人工处理；不能伪装成未实名 |

processing时的`lookup_manual_action_pending`、`lookup_recovery_required`、`lookup_outcome_unknown`都保留原ID，由平台处理；对方继续读取，不能回填空姓名或新建查询。

HTTP200和ok:true只表示读取记录成功；仍须判断status。接口网络/401/429/503错误不能写成业务failed或空姓名。无Webhook。实际耗时受手机和人工验证影响，不保证2分钟完成。

## 超时、崩溃与重试

- 2分钟是对方等待预算，超时后仍按原lookupId读取。提交响应丢失或提交进程崩溃时，以**已保存原键**重发。每次HTTP生成新Nonce/签名，SDK已经处理。
- 即使换请求号，同clientId+同手机号在途也返回原lookupId，不多查一次。成功/明确无姓名固定完成后10分钟复用；读取或重复提交不顺延窗口。
- **边界**：任务已明确失败且确认停止，或成功结果超过10分钟后，新键可能创建真正的新查询；需要保证同一业务永不重查，就跨进程、跨定时轮次持续复用原键。原键及别名至少保留7天，当前未自动清理。
- 单任务最多50个新提交别名，达到上限429；应停止换键，用原ID读取。队列满429按Retry-After退避，原业务键不变。服务不可用503不换业务身份。
- 结果回填失败只重读原结果并重试自己数据库事务，禁止因此重新提交号码。建议业务表和结果回填在同一事务；跨系统副作用用持久outbox/唯一lookupId消费，不能仅依赖内存标记。
- 未开始队列预算30分钟、总体执行预算60分钟；超期时需先停止/对账，设备离线导致停止不确定会继续保留预约，防止重复查。人工等待30分钟、账号冷却8小时由平台管理。

## 可运行示例

`partner_example.py`使用Python标准库SQLite展示独立提交/读取和崩溃恢复，不依赖平台内部模块。先在安全环境配置上述三个连接变量，PHONE_NUMBER仅用于提交；示例号码均为合成，不用于真实查名。

```sh
python3 partner_example.py submit --db /private/path/partner.db --business-id your-stable-business-id
python3 partner_example.py poll --db /private/path/partner.db
```

两条命令可由两个独立定时任务调度。对同一个业务ID重复运行submit会使用原记录/原键，已保存lookupId就不再次提交；改变该业务ID的手机号会报错。示例数据库含手机号/结果，应放私有目录并限制访问。接入方要把SQLite事务示例换成自己的业务库，并在标为完成的同一事务内回填业务表；样例不会自动修改对方系统。

## 联调前交付清单

平台方单独提供HTTP BASE_URL、CLIENT_ID、CLIENT_SECRET，确认客户端用途授权和设备池已开放，并提供对应部署版本和灰度回执。接入方先以一个已授权号码完成提交、保存ID、读取结果，再验证超时重试；不得直接以大量号码压测。

本轮修复范围是启动触限后的账号确认、拼图后自动接续、首次结果未确认时保留原任务。具体测试数量、生产生效状态与未完成项以同版本发布回执为准；模拟5路不等于5台真机实测。姓名为页面实际显示的掩码姓名。未完成生产灰度前，本包可用于接口开发与模拟验证，不代表真机验收完成。
