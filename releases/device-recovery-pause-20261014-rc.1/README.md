# 单机暂停自动恢复，本地候选

基于已上线 platform-core-20261014-rc.7 的准确组合源码；本目录为最小叠加，不使用根仓旧业务源码。未部署，不会改变线上18号的现状。

## 使用与行为

恢复控制台每台异常手机有“暂停自动恢复 / 继续自动恢复”。暂停保留发现、心跳、在线状态、短信与当前控制会话，阻止该手机后续自动ADB reconnect/PnP动作；其他手机照常调度。已开始的PnP动作/安装进程不能安全取消，等待自然收尾。暂停目标即使已在线或暂时拔出，仍显示可恢复入口。平台管理员可通过以下接口暂停已知手机；普通用户/Agent凭据无权修改。

POST /api/v1/windows-agents/{agentId}/recovery-control

请求：adbSerial（真实序列号，大小写归一）、paused（布尔）、expectedRevision（当前agent.recoveryControl.revision），可选reason（最多200字）。响应control为期望配置，不等于立即生效；health.recoveryControl.synced=true且revision相同并有新鲜心跳，才代表Agent已持久接收。409表示版本冲突或旧Agent不支持；404未知Agent/设备；503控制存储不可用。页面会显示等待确认。重复提交相同设置不增加revision；重试先读最新状态。

## 持久化、边界和回退

云端DATA_DIR/device-recovery-controls.json为独立、原子替换并fsync的数据文件，按Agent隔离，当前平台单进程写入；不依赖延迟运行状态快照，无数据库迁移。Agent dataDir/device-recovery-control.json按Agent身份校验并持久保存。更新发布后，暂停/继续操作无需重启。首次升级代码本身仍需部署窗口，不宣称可以不停机替换正在运行的Agent。

Agent每次启动先同步平台权威控制再允许PnP；同步前只等待自动恢复，不停止扫描/控制/任务。运行中保留最后确认设置；新暂停在写盘等待时立即约束该目标，继续恢复需写盘成功才放开。损坏云端控制文件保留证据、拒绝控制写入并返回不可用状态，不让整个业务平台启动失败；不自动清空暂停。旧云端不返回协议时，新Agent启动后停止自动PnP等待兼容云端，但其他链路继续。旧Agent回滚会忽略暂停，因此回滚前须保证问题手机已安全隔离/有另经授权的维护方案，不能仅回退文件即保证18不再重装。

恢复选取、异步探测后、目标锁内、写状态后的最终命令边界都检查暂停。暂停不清空原动作历史/冷却；继续后按原梯级及冷却执行。不按18号硬编码，不新增自动全局熔断，不绕过真实安装器忙/未知，不杀安装器，不换驱动、不重启ADB/USB/媒体。
