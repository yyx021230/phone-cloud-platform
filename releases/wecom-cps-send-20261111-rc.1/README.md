# CPS正式接单切换候选

用户在已授权上线基础上明确要求CPS实际接入，澄清preview不能添加后继续完成正式接单。基线为wecom-cps-preview-20261111-deployed.1，ACTIVE cfd4dcf0。本轮仅独立CPS服务配置切换，不重载主平台、Agent、ADB、Windows或媒体，不主动创建真实邀请/回调测试线索。

CPS仍用同一4c3823e7镜像、原app_id/密钥、成员200/202和HTTPS回调。只把CPS_EXECUTION_MODE改为send、CPS_STATE_KEY固定为首次正式账本production；不能把原preview账本原地改模式，不能用空账本清除防重。将三个preview账本的9条静止历史及更保守的客户防重、nonce与限频记录复制到production，源记录不动；未知、已发送、已是好友优先于not_sent，物理别名冲突拒绝。不执行旧预览、无旧业务回调。

首次正式账本初始化要求目标不存在、原9条平台任务是相同预览/终态/原请求/原设备且无发送认领，200/202没有未对账的历史send。应用时必须取得全部源与目标协调者锁，停止旧CPS后才写新账本。原账本/新种子只保存在受限备份，不进仓库；执行前先只读预检，使用实际部署的store校验数据。正常服务继续使用原store和CAS，不增加运行时协议。

本地检查60项：59通过，1个未配置隔离PG的可选用例跳过；包含11项新迁移守卫。首次缺pg依赖失败，建立仅本轮临时依赖链接后复跑。生产预检只读检查真实数据库，不用模拟替代。初次隔离operator挂载路径不可见、read-only容器不能docker cp，均未接触服务或数据库写入；改为凭据不入构建上下文的独立operator镜像，再只读预检。

切换前保存原容器、原配置、ACTIVE及D-075宿主只读证据，预创建新CPS容器但不启动；旧CPS无在途工作后正常停止，独立operator在事务内初始化新账本，新服务健康后替换原名称和持久配置。全过程不改主平台或Agent生命周期。切换后核对send状态、原历史零重放、签名设备查询与错误请求、源账本不变和主服务健康。正式新线索由CPS开发下发后再验真实邀请和自动回调。

回退：正式首单前若激活失败，保留所有新旧账本及故障证据，修正独立服务配置；主平台版本始终保持。一旦正式接单，不得回切旧preview来绕过production防重，不恢复旧数据库/删除发送认领。必要时停用新接单并保留production账本，修复后继续原模式与命名空间。旧容器保存为证据，不允许同端口或同账本并行运行。
