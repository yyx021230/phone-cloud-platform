# 账户掉线单轮隔离（本地候选，尚未发布）

## 行为及兼容

1. 仅对终态失败的 start/query/switch，以明确登录错误或准确 LoginActivity 确认掉线。忙、未知执行、一般页面错误、正常首页、保存账号列表不会被此规则直接标记。
2. 设备持久化 `accountOffline`，包含证据任务、脱敏账号/来源、通知事件和被阻止的准备轮次。它独立于 `lookupUnavailable` 的三次通用失败隔离，**不新增触限冷却、不递增通用失败计数**。真实冷却原样保留。
3. 本轮只暂停掉线手机。未完成业务保留 lookupId，原执行确认结束/停止 ACK 后才重新排队给就绪手机。未知执行不重放；取消不重新派单；已收到结果优先交付，同时仍记录已证实的掉线。
4. 相同 prepare 幂等键表示轮询/重试，不能反复解除掉线。后续显式启动用新的 prepare 键，更新内部 loginEpoch，允许该机重新探测；仍遵守探测预算和占用规则，不直接标记就绪。真实探测成功且有姓名/可信账户身份后清除掉线；未成功仍不可接业务。其他手机的就绪证明与在途业务不重置。
5. 启动时可转换旧版误隔离：只有最近三条准备/查询均有登录失效证据，才从三次失败隔离转为单轮掉线；混合离线、未知错误仍保留旧隔离。变更与 prepare 鉴权同事务，没有独立 SQL 清理。
6. 通过现有飞书通知持久化去重链路发送：`118号手机支付宝账户掉线，账号175******30需要重新授权登录。请到云手机平台实时控制完成该账户登录。本次任务暂不分配此手机；后续启动任务将重新探测，探测通过后恢复使用。这不是查询触限冷却。` 同一未解决事件不刷屏；实际恢复后再次掉线可重新提醒。
7. 账号优先取实际选中的目标，其次可信当前账号；只有历史值时明确“最近确认账号（当前登录页账号未确认）”，无法读取则明确“当前登录页账号未能识别”。不泄露完整手机号、不把设备型号作为手机编号。

## 验证和审查

详见 verification/RESULTS.json 和各日志。自审覆盖适配器→调度→持久状态→通知/管理页；没有委派或双人审查。修正了结果与终态登录失效同时到达时只返回结果却漏标手机的竞态；业务结果不重查，掉线状态仍保留。核对193个冻结文件哈希不变；index 仅扩展通知来源，未改变实时控制调用链。

初始故障复现10项中4通过6失败；首次全量834项中832通过，2条旧文档断言仍期待47个接口/11个HMAC入口，与已经上线的33接口、3个API Key查名入口不一致。本候选仅更新这些断言，同时保持路由、模块、参数及响应 schema 覆盖，不为新行为降低测试标准。

尚未做本候选生产真机/真实群通知/真实Postgres重启验收，未构建生产镜像。回环HTTP使用本机临时服务和5台模拟设备、合成号码、随机测试Key，生产连接为0；此次换键验证不是实际等待120秒，不替代既有两分钟真机验收。

## 复现与发布准备

`python3 releases/lookup-account-offline-20261016-rc.1/verification/prepare-local.py --out /tmp/pc-account-offline-repro-UNIQUE` 在全新目录组装已提交生产基线和本补丁，校验前置哈希。使用既有兼容依赖缓存或按锁文件安装到隔离目录，再执行 `npm run check`、`npm run test:screen`、`node verification/account-offline-http.mjs`。不从根仓旧业务目录启动候选。

正式发布需另获具体版本/维护授权：先核对最新 ACTIVE、运行/下次镜像与本 BASELINE，无漂移后备份数据库/旧镜像/Compose及文件；在真实媒体宿主机只读 D-075 verify --live，失败停止。只做云端镜像更新，**不重载 Agent、不动 ADB/SYSTEM/媒体**；云端重载可能短暂中断控屏，需明确当次影响范围。随后获准的单机、双机验证首次登录失效、切号失效、通知一次、下一启动探测及原ID转交。

## 回滚

本候选无SQL迁移，新增字段存于既有 managed lookup JSON。发布时保存实际上一版镜像/Compose与配置备份，不覆盖新业务数据库。授权回滚应恢复上一镜像及匹配静态资源，保留现有数据和通知回执；旧版忽略软隔离字段，会恢复旧通用重试行为，因此若必须回退，先在允许范围内暂停受影响的查名设备派单并等待在途停止，不能靠整库回退抹除结果。现有冷却、账户授权文件、Agent、ADB、媒体均不作为回滚对象。
