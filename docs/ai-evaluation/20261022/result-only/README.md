# 查询后“页面待兼容”AI读取：本地实测第二阶段

本轮按用户最新指示，只测试指定服务的`gpt-6.1-sol`在**本次号码查询已执行、进入“页面待兼容”**这一处补读结果。先本地测试，未修改业务代码、数据库或线上配置；之前的接入草稿不作为可发布代码。

## 固定返回规则

对外继续使用现有接口原格式，姓名字段只允许：

- 读到明确姓名：原样返回既有姓名显示值，不补全星号遮盖内容。
- 未实名、完整结果没有姓名、AI无法识别/判断、AI调用失败：均为空字符串`""`。

**不新增“未实名”“没有”“无法确认”这样的姓名返回值，不新增状态、错误码或字段。** 本地诊断可以区分原因，但不送入外部API。空表示本次最终没有取得可返回姓名；包括用户明确指定的无法判断兜底。

本规则只覆盖这一个查询后兼容点，启动、首次就绪、切号、冷却、账号登录、设备离线、全部设备不可用、取消/结束等既有流程与返回不在本轮修改范围。AI不决定这些操作。原查询ID、请求防重关系及已有完成结果必须保留，不能重复提交号码或用兜底空值覆盖已确认姓名。

## 真实模型实测

本轮最终45个场景全部符合预期：13个姓名场景返回正确显示名，32个场景返回现有空字符串。34个场景使用已保存真实截图（其中错订单复用一张图），11个使用新生成的合成测试图；合成图不冒充真机证据，没有编辑原始截图。相同有姓名图的预期值已逐图核对；空结果覆盖历史12种完整布局。

| 覆盖内容 | 最终对外姓名值 |
|---|---|
| 普通单卡、邮箱带号码、同号双卡、长昵称 | 该卡可见姓名显示 |
| 完整个人卡与多张企业卡混排 | 完整个人卡姓名显示 |
| 邮箱/昵称后标未实名 | `""` |
| 仅充值、转账加充值、下方推荐或大片空白 | `""` |
| 明确未找到提示 | `""` |
| 只剩搜索框/空白、截断、加载残留、黑屏 | `""` |

第一次42场景中41个达到读取预期，企业混排1例未取到姓名。按最终返回规则那时会给空字符串。随后只调整本地试验提示与结果关联：可辨认企业卡不阻止完整个人卡读取；冲突/无法辨认的个人卡仍不给猜测姓名。保存了首次结果和草稿哈希，补测后再完整重跑最终45场景，全部通过。旧结果没有被覆盖成“首轮全通过”。

最终完整回放单次调用耗时最短3.967秒、中位7.047秒、最长26.982秒；是本机、指定服务、本组截图的实测，不代表生产全链路耗时。另独立重复企业混排、未实名、充值后空白三例，读取结果与现有接口投影完全一致。第一轮42次、混排定向1次、最终45次、重复3次，共91次推理；上一阶段20次是另一次实验，不混算本轮。

## 固定接口格式检查

52项本地校验通过，包括三类结果读取证据、公司混排/空白边界、错误号码、串卡、缺按钮、完整性，以及使用**已发布基线的`publicAsyncLookup`函数**投影验证：

- 返回键仍只有既有`ok`、`lookupId`、`status`、`name`；正常终态仍`completed`。
- 姓名只保留已识别显示值，其余均`""`；空值、非法响应、内部文字标签或AI错误不会新增返回值。
- 不在查询后兼容点、不满足查询已完成、已有终态或执行中/未知状态时，不应用这一替换。
- 原查询ID与原期限保留，已有姓名不被空覆盖。

这是本地读取器和既有响应投影函数检查，不是HTTP服务/真实订单写回/手机停止ACK验收。测试诊断JSON里的`expected/actual/source/error`是实验记录字段，**不是新增接口字段**。脱敏数据与程序哈希见[RESULTS.json](RESULTS.json)；原图、原始模型输出和含个人数据的测试输入仅留私有临时目录，不入Git。
