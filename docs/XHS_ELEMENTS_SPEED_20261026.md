### 变化及不变量

1. 新增短命 `NativeWindowPair` 进程，复用既有 `NativeWindowReader` 原生读树算法。连接初始化2秒，第一棵完整树，间隔2秒，再读第二棵完整树；每次根读取都清理该进程的Accessibility缓存。两次读树的根ID、窗口ID、连接ID必须一致，每棵树仍验证节点身份、包名、几何和完整性。
2. Android API低于24不启用。首次需要两棵新树的标题、日期、状态、观看/点赞/评论及边界标记，与旧路径已证明页面一致。首屏就到30天日期边界或列表末尾时不做试读。
3. 滑动后的两棵完整树必须相同，出现新笔记身份，且两棵分别与前页重叠才接受。原有滑动距离、最大滑数、日期顺序、去重和不完整判定不改。稳定但无重叠直接停止，不能继续滑动掩盖漏行。
4. 不支持、慢首读、快照不一致、停滞等首次发生后，本任务关闭快路径，走已有刷新及加载重试。取消、错槽、未知进程退出、超时、断开/临时文件清理无法确认等不当作普通兼容重试。退出登录仍归为账号错误。
5. 保持远端`timeout 20`、Python25秒及Agent原有25秒取消宽限；首棵读取超过3秒就正常拒绝双读，避免两次各12秒读树预算叠加超出既有范围。该时间预算不是对阻塞Binder调用的硬保证，最终仍依靠原有远端/主机超时；设备取消长尾待真机确认。
6. 结果schema不变，仅向既有事件列表添加入口耗时、重回最新列表耗时、试读耗时、翻页读树累计毫秒和快路径页数。无账号名、标题、密钥等新增日志。
