## 2. 按顺序调用

联调包解压到同一目录，使用Python3（无需安装pip依赖），运行：

```sh
python3 cps_local_client.py health
python3 cps_local_client.py devices
```

在Windows可将python3替换为已安装的Python3命令python。示例客户端会读取同目录私有配置，为每次请求重新生成时间戳、nonce和签名。stdout展示完整业务字段，客户号码与sign脱敏，wecom_phone明文展示。

- 200 → wecom_phone：17508437040；wecom_name：小文；默认lead_id：61120200。
- 202 → wecom_phone：13067238489；wecom_name：小文；默认lead_id：61120202。

- 手机保持USB连接，Mac保持运行；在当前手机执行期间不要手动操作该台企微。可以从另一台空闲手机独立执行。

每条新任务启动手机上该企微主号的新进程，然后开始搜索和核验。CPS重试沿用原lead_id和业务字段，更新nonce及签名，平台复用原任务。使用示例客户端下发时，须显式指定CPS登记的测试线索ID。发送结果或备注保存状态不明时，先核对原任务和手机结果。

不同客户使用不同lead_id；同一条业务的重试始终沿用原lead_id。多客户可向不同空闲手机并行提交，同一手机只允许一个原生执行；已受理的队列逐条处理。若返回忙碌code=2003且success=false，本条未受理，等待可用后按原lead_id重新签名提交。不能把忙碌拒绝当成已经排队，也不需要等待另一台整轮结束。

## 3. 如何判断结果

HTTP 200、success=true、code=200表示下发已受理。手机核验客户及备注手机号后发送一次。收到企微明确的发送证明后，按原线索自动回传。运行中查询可见busy=true，清理确认后设备恢复空闲。CPS以结果回传更新线索。

CPS接收端使用双方确认的局域网测试回传地址。应答为HTTP 200且响应体中success=true、code=200时，平台将通知记为完成。回传超时或服务端错误只重试原通知，重新生成签名，手机任务只执行一次。

原协议仅接受success/duplicate/添加过频的failed。普通页面、登录、连接和发送未知错误保留真实原码待处理；双方通用失败约定仍未完成。开发不能把没收到回调或设备空闲当成添加成功。

## 4. 实际边界

本地服务使用隔离的受限文件账本和仅本机监听的CPS核心，局域网入口由当前QA Node代理转发；不是修改正式bridge的监听地址，也未启动Nginx、修改防火墙或生产配置。新测试服务与上轮已结束的观察服务使用不同接入应用和独立账本，之前的私有观察地址不能复用。停止或重新运行时保留账本和原任务；崩溃后不删owner文件或猜PID清锁，先核实本地进程和手机资源。

原联调包准备阶段未触发新手机执行；随后已按用户要求补双机、多条任务及逐次重启验证，完整记录见verification/wecom-cps-multi-20261105。联调包rc.2的默认lead_id为预留的新测试任务号，旧rc.1默认任务号已用于验收，会防重而不重新操作手机。正式Windows/CPS公网、真实发送、长期运行仍待后续验收；本入口不解除任何生产冻结。
