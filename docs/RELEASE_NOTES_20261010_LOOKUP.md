## 账户冷却与限制分类

8小时是本项目的调度冷却策略，不表示支付宝官方限制时长。仅 `access_denied`、`device_risk`、`frequent_or_abnormal_access` 三类精确限制，且账户归属已核验时，才写入账户冷却。号码输入前遇限也可以记录，但保留 `phoneQueryStarted=false`，不归因于该号码。

重复事件不延长冷却；到期保留历史。身份不明确、保存未确认、网络或普通页面异常均不盲目切号。只有完整账户列表证明全部账户均在冷却，才暂停该手机后续号码。限制页面上的“反馈码”不再单独作为拼图证据；准备阶段普通滑块调用既有处理器，真实拼图始终由人工完成。

## 提醒与人工接续

提醒使用库存中的具体手机编号，例如：

> 118号手机出现拼图，请人工介入到云手机平台实时控制完成拼图。

118是当前测试机的已确认映射，生产按各设备实际编号生成文案，不硬编码为118。没有有效编号时不回退到测试名称、型号或ADB序列号。消息不包含查询号码、姓名、账户或截图。

同一次拼图先持久化发送记录，再尝试通知，服务重启不重复发送；同一原查询恢复后再次遇到新的拼图，可以重新提醒。超时或未知受理结果不自动补发，不能承诺消息必达。Webhook从受限配置文件或环境变量加载，默认未配置时禁用，实际地址不写入仓库。

首次账户准备阶段遇拼图时保留会话与占用，不伪造查询结果；人工完成后先继续账户准备，再执行排队号码。查询阶段恢复沿用原号码、原结果和外部业务引用。普通恢复失败显示“重试当前号码”或“重试账户准备”，这个入口与拼图完成确认无关。

## 本轮审核修复的六项缺口

1. 查询已成功而结果上传失败时，保留原成功报告重传，不再改报业务失败或重新查号。已落盘报告可跨Agent重启继续发送；未成功落盘时仍有进程崩溃丢失风险。
2. 服务端终态保存失败后，重复上报重试原保存操作，持久化成功才确认；并发或迟到报告不覆盖已胜出的结果，不重复计数或派发。
3. 网页与Open API结束会话时，停止任务、原运行任务及其取消记录一并保存。
4. 人工后恢复发生普通异常时，原号码进入 `needs_recovery`，暂停后续队列且不发送拼图提醒。
5. 首次启动遇到真实拼图时，保留可恢复的启动状态，补齐通知和自动接续。
6. 账户准备阶段按验证类型区分普通滑块与拼图，修复普通滑块误转人工的问题。

## 外部调用方兼容说明

HMAC认证方式、接口路径、号码脱敏、查询身份和幂等原则保持不变。调用方需要按动作区分两种暂停状态，不能把所有 `queue_paused` 都解释为账号耗尽：

| 返回状态或动作 | 调用方处理 |
| --- | --- |
| `humanAction.required=true` | 人工处理拼图并持续轮询；首次启动没有查询ID，不调用查询恢复接口 |
| `needs_recovery` 与 `queueState.action=retry_current_query` | 对返回的原 `queryId` 显式调用 `/resume`，或结束会话；不是拼图，也不是换设备指令 |
| `queueState.action=end_session_and_select_another_device` | 结束当前会话，选择其他可用设备 |

首次账户准备恢复失败没有查询ID，由网页“重试账户准备”接续。现有Node/Python SDK会返回 `queue_paused`；本次未修改SDK运行代码，接入方须读取其中的 `queueState.action`，不能沿用“暂停就换设备”的单一处理。[接口契约](OPEN_NAME_LOOKUP_API.md)

本次未新增SQL表迁移；冷却、人工恢复等字段沿用现有JSON/data/payload存储。Agent新增 `dataDir/lookup-status-outbox`，云端提醒使用 `DATA_DIR/lookup-human-notifications`，两处均需要持久、受限且可写的目录。

回退须配套处理云端、Agent、Python与网页，先核对原任务及未确认报告，不删除冷却历史、通知回执或待确认结果，不整库覆盖、不重复提交号码。既有未提交工作不能随本次候选整包带入生产。

投屏、编码、帧率、画质、控制映射、ADB/USB/PnP不属于本次更新。必须保留D-075自定义媒体二进制及systemd配置，每个观看连接8 Mbps、最多2包一组的基线不变；正式发布前后按主文档在实际媒体宿主机只读核验，不以本地哈希检查代替生产核验。

本地测试管理员凭据调整、实验拼图求解器、临时批次保护和其他未发布功能不列入本次更新。
