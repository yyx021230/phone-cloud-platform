# CPS企微三接口：本地候选验收与启用说明

日期：2026-11-04（备注名规则更新）。协议依据：[双方对接方案v0.1](CPS企微客户对接方案-v0.1.md)。本次为本地候选，未部署、未推送，未连接生产手机或真实CPS服务。

## 本次实现

| 方向 | 接口 | 行为 |
|---|---|---|
| CPS→平台 | POST /api/v1/lead/dispatch | Body签名；可靠保存后立即返回；显式成员映射定位手机主号／分身 |
| 平台→CPS | POST /api/v1/lead/callback | 只回传申请明确提交、已是好友、真实添加频繁；回调重试不重复操作手机 |
| CPS→平台 | POST /api/v1/lead/devices/query | 默认全部设备，可筛在线；分别报告成员、物理占用和全局容量 |

回调是向CPS固定配置地址发出的请求，不是本平台提供的接收接口。原四字段Bearer企微接口继续保留；支付宝查名字接口、池配置及结果协议不变。

按2026-11-04最新要求，备注名只用完整`lead_id`十进制文本，替换此前的`手机号_线索ID`。描述保留`leadId:完整线索ID`，客户手机号继续独立搜索和核验。备注名上限仍为20码点，合法正INT64最多19位，均可原样使用，不截断、不丢精度；调用方也须无损构造与签名INT64，官方事件匹配按完整线索ID对齐。

## 内部隔离和防重

- 独立可选进程`server/cps-wecom/main.mjs`，仅监听本机8797；平台主进程不自动启动桥接服务，不加载额外.env，不引入新依赖。
- 独立账本包含线索、nonce、原任务、成员限频和逻辑客户防重；`app_id+lead_id`保证同线索幂等，企业＋成员＋客户的哈希防止换线索或迁机绕过已发／未知记录。
- 先持久化原执行意图，再发平台提交。提交响应丢失只按原requestId核对；找不到原任务留待处理，不盲目创建第二次添加。平台明确未受理的忙碌响应才可保留原请求排队。
- 同手机主号／分身继续共用平台既有物理互斥。查名、控屏或其他任务占用时不接管；库存查询只读已有状态，不扫描、不安装、不恢复手机，也不主动过期设备锁。
- 已发送或发送未知保留防重。仅终态、发送未尝试、无发送凭据、保存非未知且物理清理已确认时，才允许后续新线索重试相同成员与客户。
- 回调仅收到HTTP成功且Body `success=true, code=200`才完成。最多5次，间隔5/10/20/40秒，每次新nonce和时间戳；回调失败不回到手机执行阶段。跨进程重启保留阶段和尝试次数。
- 限频立即冻结对应官方成员，其他成员不继承；有可信任务完成时间时按北京时间当日24:00到期。无可信时间持续保守冻结，留待处理。过午夜的旧限频回调暂停发送，避免CPS误停新一天；此处仍待双方补充跨日协议。
- nonce至少保留5分钟，并覆盖请求时间戳的剩余有效窗口，防止客户端时间偏快时在有效签名内重放。

## 明确结果和异常

备注手机号必须在已知完整备注表单的独立电话编辑框内核对，正确才能声明`remark_phone_set=true`；备注名或描述包含号码不能代替。无法核验时停在发送前。

申请明确提交使用新增的严格原生系统对话框证明；必须是原租约、原前台应用、发送后的两次新鲜一致页面和完整固定文案。单击成功仍为发送未知，不认为客户已通过；既有发送凭据及未知不重放保持。添加频繁同样只接受固定原生系统消息，不从客户昵称或通用异常推断。

**这些新原生证明目前只有合成页面和模拟Agent验证，没有本轮真机证据。** 若真实企微版本不暴露该确切结构，就会保留未知而非报成功，须在另行授权的灰度中验收，不能凭本地模拟宣称已可生产全量使用。

原CPS协议不接受登录失效、搜索不到、离线、人工验证和发送未知等通用失败；这些进入`needs_attention`并保留原码，不伪报成频繁或成功。桥接进程只输出脱敏阶段计数／fenced状态；维护人员可从独立账本和平台原任务核对。对外未增加未经约定的第四个业务接口。

## 显式配置与启动边界

启动前由部署人员在安全环境注入配置，不把真实密钥写到仓库、示例或日志：

| 环境项 | 要求 |
|---|---|
| CPS_WECOM_ENABLED | 必须显式为true，否则拒绝启动 |
| CPS_EXECUTION_MODE | 必须显式preview或send；preview从不发送邀请或结果回调 |
| CPS_WECOM_CLIENTS_JSON | 接入appId、secret、固定callbackUrl、allDeviceStatus及members；凭据用安全渠道注入 |
| members | 每项含wecom_corp_id、wecom_userid、deviceNumber、appSlot(main/clone)、enabled、bindingVerified |
| CPS_PLATFORM_BASE_URL / CPS_PLATFORM_TOKEN | 内部平台地址与平台管理员凭据，仅桥接端使用，不交给CPS |
| CPS_DATABASE_URL | 生产必须PostgreSQL；仅连接独立CPS账本，不能用文件模式代替 |
| CPS_STATE_KEY | 稳定账本命名空间，默认default；不能为重试、迁机或切版本更换以绕过防重 |
| CPS_DATA_DIR | 仅本地文件测试使用，默认data/cps-wecom；目录/账本受限权限 |
| CPS_PORT | 默认8797，仅绑定127.0.0.1；对外HTTPS入口需另行准备和授权 |

同一官方企业＋成员不能在多个客户端重复配置，同一个手机槽位也不能绑定多个成员。`bindingVerified`缺省为false；未核验不执行。现有真实映射表仍待补，不能用示例值启用。更换实际登录成员时先停用原映射并核验新绑定。

生产回调必须HTTPS；内部平台凭据也仅通过HTTPS或本机回环传输。仅本地测试可配置allowLoopbackTest=true的回环HTTP回调，不向公网开放测试接收器。服务启动命令为`npm run start:cps-wecom`，不会顺带重启平台或Agent。

执行模式写入账本后不能将同一预览账本改成发送账本。正式环境首次启用前须核对原平台发送记录，不能把新建空账本当成清除原防重的许可；迁机继续使用原生产账本。

## 持久化、失败和回滚

`deploy/sql/cps-wecom.sql`仅新建独立`phone_cloud_cps_wecom`表，schema版本2；不修改设备、查名或其他任务表。生产有Postgres会话级单协调者锁及revision CAS，失去连接、写入结果不明或版本冲突即fenced，停止后续操作。文件测试使用独占owner文件和fsync；崩溃遗留owner不自动抢占，须人工核对原进程已退出及账本完整。

早期未发布v1原型账本不会静默升级。若现场已有v1表／文件，先备份并核对所有原任务及发送凭据，再单独审核转换方案；当前候选拒绝启动，不覆盖它。SQL的IF NOT EXISTS也不会替已存在表改约束。上线前还须核验生产数据库约束、备份及恢复演练。

回滚先停止桥接接单并保留原在途／回调记录，再按真实发布基线回退代码；**不得DROP/TRUNCATE账本、恢复较旧发送记录、删除发送凭据或改state key重跑**。可回退新增程序，不可撤销已经发生的邀请。若涉及共享平台或Agent重载，必须按维护范围另行取得批准，不能借本次本地开发执行。

## 本地验收与未验项

本轮检查明细与源码哈希见`verification/cps-wecom-contract-20261103/REPORT.md`及manifest。测试以虚拟时间、合成原生页面、回环HTTP和临时独立PostgreSQL运行，不连接生产ADB、真实手机、真实CPS或飞书。

覆盖签名／INT64、20字符、主号／分身、重复nonce、超时换线索、重启／迁机防重、提交丢应答、回调重试、限频单成员隔离与跨日保护、未知不伪报、账本写失败阻断及查名占用不抢占。根投屏回归和Agent检查分别执行；没有用静态测试替代真机验收。

启用前仍需：真实官方成员映射与登录核验、双方普通失败／跨日协议、按完整线索ID的官方事件匹配联调、实际HTTPS入口与安全凭据、生产数据库与持久账本核验，以及获授权真机单机／双机灰度。当前未上线，不承诺生产全量验收或绝对无故障。


## 独立CPS客户端回归入口

本地候选增加`npm run test:cps-wecom:client`。它不直接调用服务方法：独立签名客户端、CPS回调接收器、桥接子进程、实际平台子进程及丢回包代理之间均经回环HTTP；模拟Agent只上报合成结果，不连接手机。默认缩短“未收到最终结果”的等待；其通过不能当作真实两分钟计时验收。

要真实等待超过两分钟，测试进程环境显式设置`CPS_WECOM_LONG_E2E=1`后运行同一入口。可另设置`CPS_WECOM_E2E_DATABASE_URL`使用专门的本地`cps_wecom_client_fixture`数据库，只有127.0.0.1或localhost且数据库名精确匹配才允许；不传时使用临时JSON账本。测试会在独立库应用CPS表SQL，不得注入生产数据库。必须在没有根.env的独立工作区运行；检测到.env时测试拒绝启动，不替用户删除或改名。

覆盖CPS受理回包丢失、平台提交回包丢失、并发重复／更换线索、真实回调500／断连／5秒超时／业务签名拒绝、在途与回调账本重启恢复、主号／分身的Android user定位、同机排他及容量、受理后查名抢先占用的竞态、发送未知和成员限频。对平台明确未受理的409占用，允许同一原请求重试；“平台POST次数”必须与“实际创建任务／领取／发送尝试次数”区分，不能为了零重试而跳过平台互斥。

本轮验收记录另见`verification/cps-wecom-client-e2e-20261103/REPORT.md`；仍为本地模拟，不取代真实登录身份、原生结果证明、HTTPS和双方正式联调。


## 2026-11-03 生产内部预览的阻塞事实

本地CPS候选仍未上线。为执行用户授权的空闲主号／分身预览，本轮向旧生产32c内部预览API提交1条155/main、mode=preview。原任务在宿主进程登记阶段失败wecom_cleanup_host_unconfirmed，未放行手机业务配置；原结果无发送凭据、invitationSent=false，remarkSaveStatus=unknown保持。155留下awaiting_host的单机清理义务，分身未测，不是主号或CPS完整真机验收通过。
