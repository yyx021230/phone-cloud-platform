## 已确认原因

1. **技术故障进入设备隔离**：生产 `lookupFailureDomain` 将HTTPConnectionPool/worker退出归device；失败截图AI只接受page域。138、142、155、158的原图实际有姓名，却在读取超时分支结束，未进入这一截图AI入口。这是执行/恢复和分类链路问题，截图不能证明账号当前受限；也不能据一次旧截图直接授予现在的就绪资格。
2. **旧隔离长期保留**：生产lookupUnavailable为持久布尔；quarantineUntil到期并不会清除。13台中8台隔离来自10/23，2台10/26，3台10/27。仅凭当前隔离卡无法断言手机仍故障。rc.7继承的受控重探仍是本地候选，尚未上线。
3. **后台历史证据查询缺口**：生产overview与job详情只查询state.automationJobs/windowsTasks。13个隔离job详情，11个实际HTTP404，142/192返回200；然而13个都能按主键从Postgres归档取回。11台overview的lastFailure为空。生产状态保留有界任务集合，旧隔离记录仍存在、旧job已不在当前集合，详情没有归档回查。
4. **并非都没截到图**：7台归档finish事件有screenshot证据及原图数据，本轮成功恢复并逐张查看；其中5台（138、149、155、158、188）后台详情404，另2台可显示。其他6台最后隔离任务无截图记录，不能补造当时画面。错误栈被截断时也不能猜测底层故障。

## 修复方向与候选边界

延续既有“本机有界恢复、原ID接续、技术故障与账号限制分开”的决策，不清线上隔离、不把RPC超时直接写账户冷却。

- 隔离详情应按阻断job ID读取；当前内存缺失时，受管理员权限控制地按主键回查归档job/task和所属证据，仍验证同一任务、设备和资源归属。不能把全量历史重新装入内存，也不能用过期签名URL当新入口。
- 持久保存每次实际计数事件的阶段、时间、错误类型、恢复尝试与证据引用，准确展示三次计数链；无图明确显示“未取得截图”及已知原因，区分归档不可达、证据缺失、采集失败。
- 已进入结果页但读取器超时的路径先走现有有界恢复；恢复失败后，只有原任务/号码/输入提交及截图时间关系成立的结果图，才考虑视觉兜底。首页或输入页不能靠AI当成空结果，真实断线仍隔离/转交。
