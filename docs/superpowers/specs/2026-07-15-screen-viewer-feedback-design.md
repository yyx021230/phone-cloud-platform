# 实时投屏画面内反馈

## 目标

用户点击“开始投屏”后，首个可感知反馈必须出现在手机画面区域中央，而不是只出现在页面顶部或右侧控制栏。

## 交互

- `connecting`、`preparing`、`ready`：显示居中半透明遮罩、加载环和当前状态文案。
- `live`、`streaming`：首帧到达后隐藏遮罩；顶部保留精简在线状态。
- `failed`：画面内显示失败原因及“重新连接”按钮；不遮蔽用户看到的最后一帧。
- `idle`：保留现有“手机画面尚未连接”空状态。

## 约束

- 不改变投屏 API、会话状态机或控制输入逻辑。
- 复用现有 `userScreenStatus`、`userScreenDetail` 和开始投屏方法。
- 在移动端保持遮罩、文案和按钮可见且不超出手机画面。

## 验证

- 启动会话后，画面中心立即出现加载层。
- 收到首帧后加载层消失。
- 模拟失败状态时，画面中心展示失败文案和可用的重连按钮。
