## 本地候选行为

1. Agent 的小红书入口在任何设备动作前，只读取本地库存，最多等待 30 秒，500 ms 一次。只有新鲜库存中的序列号、手机名、在线状态，以及本次 jobId / appSlot / xhs_data_collect 占用全部吻合才启动。空占用也要等待本次预约可见，不伪造缓存或放宽现有 Python 门禁。
2. 仍是他人占用或本次预约未同步时，返回明确的 `xhs_data_reservation_pending`、version=1、before_device_actions、collectionStarted=false、jobId 和 appSlot 证明。没有 collection；共享执行器报告失败，批次层据此转为等待。状态回传出错时不执行失败截图/元素取证，不重发不确定采集。
3. 批次仅对上述完整证明、身份/请求引用吻合、无结果的已终态任务重新排队。保留每次 jobId、请求引用、提交/确认时间和原因；30 秒后再次通过库存/占用及正式任务 API 检查。新尝试使用新引用；丢失回复只按当前引用查原任务，不重复 POST。同手机另一槽位不能绕过等待间隔，其他空闲手机继续填补最多 5 台的容量。
4. 库存过期/损坏、离线/未授权、绑定错误、运行中占用、旧版模糊错误、有部分结果、取消、未知提交均不适用这个自动重试。已有恢复账本检查继续保留。
5. 到 06:00 仍等待的项明确标记 `device_busy_window_expired`；停止批次同样停止后续派发。已运行任务继续查原结果。没有延长调度窗口，没有修改 18/152 等排除名单，也没有补跑今天已结束的失败项。

R2 本地任务；上线/真机属于 R3，需按 AGENTS.md 绑定具体候选授权。新 Agent + 旧批次遇到前置等待超时仍会标失败；旧 Agent + 新批次的模糊错误仍不重试，因此需配套验收。新 JSON 字段是附加字段，不迁移表；回退不能删除尝试或采集结果。回退旧引擎前需停止未派发项并等在途任务终态，防止旧引擎忽略新等待间隔。
